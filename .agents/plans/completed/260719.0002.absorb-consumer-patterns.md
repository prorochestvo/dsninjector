# Task Breakdown

## Overview

Five consuming projects (`com_lingocrm_api`, `beacon`, `hive`, `wordhunter`,
`vpntunnel`) independently grew the same helpers on top of `dsninjector` because
the library stops one step short of the job: they hand-roll `strconv`/
`time.ParseDuration` on `Option()` results, reimplement password redaction,
throw away real parse errors to avoid leaking secrets, hand-build
`DataSourceMapper` map literals and full `DataSource` stubs in tests, and
hand-code "field X must be non-empty" checks. This plan absorbs those proven,
cross-reped patterns back into the library so consumer code shrinks and the
recurring boilerplate disappears.

Scope is **library changes only**, **additive and backward-compatible**,
**stdlib-only at runtime**. Every change is either a new method on the concrete
`*DataSourceMapper`, a new free function, or a bug fix to an existing exported
function. The exported `DataSource` interface is **not widened** — it is
implemented by consumer test doubles, so adding a method to it would break their
compilation. Per-consumer migration is explicitly out of scope (follow-up work).

Each task below quantifies the consumer boilerplate it removes ("Consumer rent")
so the review gate can judge whether it earns its place in a library whose value
is being small. Items that did not clearly pay rent were dropped and are listed
under "Deferred to plan 003".

## Assumptions

- The DSN-**validity** bug from the review notes (`https://google.com` and
  `tbot://TOKEN` should be valid; today a base or user/password segment is
  effectively required) is a **separate concern handled in its own plan (001)**.
  This plan does not change *what Parse accepts* — only error *text* (Task 4) and
  serialization (Task 2). If plan 001 also edits `parser.go`'s `Parse`, the two
  touch different lines (matching logic vs. error strings); coordinate at merge.
- Consumers hold the result of `Parse`/`New`/`MustParse` as the concrete
  `*DataSourceMapper` and the result of `Unmarshal`/`UnmarshalOrEmpty` as the
  `DataSource` interface. Making the new methods reachable on the env path is the
  motivation for Task 9; it is isolated so it can be accepted or rejected alone.
- The reserved key **string values** (`"driver"`, `"hostname"`, `"port"`,
  `"login"`, `"password"`, `"database"`) are data tokens shared with consumer map
  literals and Parse output; they are frozen. Only their Go identifiers change
  (Task 1).
- Recon repetition counts cited below are taken as given from the review; they are
  the rent justification, not re-measured here.
- Go 1.23.3 is available, so `cmp.Or` (Go 1.22+) may be relied on in guidance to
  consumers (Task 5). No new runtime import is introduced by any task.
- Gates that must stay green after every task: `gofmt -l .` (empty),
  `CGO_ENABLED=0 go vet ./...`, `CGO_ENABLED=0 go test -race .`, and the
  compile-time check `var _ DataSource = &DataSourceMapper{}` in `source_test.go`.

### Task 2: Fix `Marshal` into a round-trippable, deterministic serializer

- Description: `Marshal` (parser.go:16) is broken and untested. It base64-encodes
  credentials via `AuthBasicBase64()` (producing `driver://<base64>@host/db`,
  which `Parse` cannot invert), always emits `@` and a trailing `/` even with no
  credentials/database, and iterates `OptionsNames()` in map-random order
  (non-deterministic output). `TestMarshal` is skipped. Replace the body so
  `Marshal` emits a `Parse`-compatible `driver://[login:password@]addr/database?opts`
  string, extract a single shared unexported assembler `assembleDSN(ds DataSource,
  password string) string` (so redaction in Task 3 reuses the exact same format —
  one home for the serialization decision), sort the query keys for deterministic
  output, and implement `TestMarshal` as a round-trip suite. Keep the exported
  signature `Marshal(dsm DataSource) (string, error)` unchanged (return a `nil`
  error) so no caller breaks. `assembleDSN` lives at the bottom of `parser.go`
  (unexported helper) next to `Marshal`.
- Consumer rent: gives consumers a correct round-trippable serializer (the
  library's stated purpose) and un-breaks the pair with `Unmarshal`; provides the
  single format home that lets `beacon`'s `RedactURL` (~8 lines + test) be deleted
  via Task 3.
- Acceptance Criteria:
  - For every **network-form** case in `TestParse` (those with a `//authority`),
    `Parse(Marshal(Parse(src))) ` is deep-equal to `Parse(src)` (value round-trip,
    order-independent).
  - Credentials are emitted iff login **or** password is non-empty, always with a
    colon separator (`login:password@`, `login:@`, or `:password@`); no `@` when
    both are empty.
  - Database segment is emitted (`/db`) iff `Database()` is non-empty.
  - Query tail is present iff there is at least one option, keys sorted
    ascending (`sort.Strings`), rendered as `?k1=v1&k2=v2`; an option with an
    empty value round-trips (`?option1=`).
  - `Marshal` never returns a non-nil error for any input.
  - `TestMarshal` is un-skipped and green under `-race`; it asserts at least one
    exact-string output to lock determinism (sorted query).
  - **Consumer regression guardrail:** `TestMarshal` includes the Telegram
    token-trick form `tbot://<chatid>:@<botid>:<secret>` and asserts `Login()` and
    `Addr()` survive `Parse(Marshal(x))` (chat id in login, full `<botid>:<secret>`
    token rejoined by `Addr()`). Multiple downstream projects depend on this form.
- Pitfalls & edge cases:
  - **Behavior change (flag in commit body):** output changes from base64 creds
    to plaintext creds. Classify as `fix:` — the old output was non-round-trippable
    and unverified (skipped test); recon shows no consumer depends on it (they
    hand-roll assembly precisely because Marshal was unusable). Note it explicitly
    at review.
  - Socket/file forms (`mysql:/var/run/...sock`, `sqlite:/path`, `file:name`),
    values needing percent-escaping (`@`, `:`, `/`, `%` inside creds/host/db/opts),
    and database values that contain or normalize a leading slash do **not**
    round-trip and are **out of scope** — that requires a `net/url` engine,
    deferred to plan 003. Concretely, a trailing-slash authority DSN such as
    `tbot://chatid:@botid:secret/` parses to `Database()=="/"` (regex backtracking),
    and re-emitting `/` + `"/"` does not invert; assert `Login()`/`Addr()` survive
    (they do), not full-string equality. Document this boundary in the `Marshal`
    godoc and keep these forms out of `TestMarshal`'s full round-trip assertions.
  - The slash-less credentialed form `tbot://chatid:@botid:secret` *does* parse on
    the current parser (verified), so Marshal omitting the trailing `/` for an
    empty database is re-parseable and carries no plan-001 dependency for that form.
  - Driver-less input (`//host/db`) must emit `//host/db` (leading `//`, no
    `://`), which Parse accepts (verified).
  - Map iteration order is random — sorting is mandatory, not cosmetic.
- Code Example:
  ```go
  // assembleDSN builds a Parse-compatible DSN, substituting password so callers
  // can pass the real secret (Marshal) or a mask (Redacted). Single home for the
  // DSN serialization format.
  func assembleDSN(ds DataSource, password string) string {
      var b strings.Builder
      if d := ds.Driver(); d != "" {
          b.WriteString(d)
          b.WriteString("://")
      } else {
          b.WriteString("//")
      }
      if login := ds.Login(); login != "" || password != "" {
          b.WriteString(login)
          b.WriteByte(':')
          b.WriteString(password)
          b.WriteByte('@')
      }
      b.WriteString(ds.Addr()) // host[:port]
      if db := ds.Database(); db != "" {
          b.WriteByte('/')
          b.WriteString(db)
      }
      names := ds.OptionsNames()
      sort.Strings(names)
      for i, n := range names {
          if i == 0 {
              b.WriteByte('?')
          } else {
              b.WriteByte('&')
          }
          b.WriteString(n)
          b.WriteByte('=')
          b.WriteString(ds.Option(n))
      }
      return b.String()
  }

  func Marshal(dsm DataSource) (string, error) { return assembleDSN(dsm, dsm.Password()), nil }
  ```
- Complexity: Medium

### Task 3: Add `Redacted()` and `String()` to `*DataSourceMapper`

- Description: Add `func (dsm *DataSourceMapper) Redacted() string` that returns
  the full DSN with the password component masked as `xxxxx` when non-empty
  (mirroring `net/url.URL.Redacted()`), reusing `assembleDSN` from Task 2 so the
  format has exactly one home. Add `func (dsm *DataSourceMapper) String() string`
  that delegates to `Redacted()` so `fmt`/log of a `*DataSourceMapper` is
  secret-safe by default (today `fmt.Sprintf("%v", dsm)` prints the raw map,
  including the password — an active leak). Both methods live in `source.go`
  alongside the other value methods (consistent with `AuthBasicBase64`). Add
  godoc: `String`/`Redacted` are for display/logging and do **not** round-trip
  (password masked); use `Marshal` for a complete serialization. As part of this
  task, add a godoc note on `Addr()` documenting the field-repurposing convention
  some drivers use — e.g. a Telegram DSN (`tbot://<chatid>:@<botid>:<secret>`)
  packs the chat id as the login and the bot token across host:port so that
  `Addr()` returns the full `<botid>:<secret>` token and `Login()` returns the
  chat id. This is the Pattern 6 resolution: document the convention, do **not**
  add Telegram-specific API.
- Consumer rent: deletes `beacon`'s `RedactURL` (~8 lines + its test); removes the
  ambient leak risk of logging a `*DataSourceMapper`.
- Acceptance Criteria:
  - `Redacted()` on `postgres://user:password@localhost:5432/db` returns
    `postgres://user:xxxxx@localhost:5432/db`.
  - When password is empty, `Redacted()` emits no `xxxxx` and preserves
    login-only credentials (`login:@`) or omits credentials entirely when login is
    also empty.
  - `String()` returns the same value as `Redacted()`.
  - Table-driven tests (`TestDataSourceMapper_Redacted`, `TestDataSourceMapper_String`)
    assert the password value never appears in the output when it was non-empty.
  - `var _ fmt.Stringer = &DataSourceMapper{}` compiles (add to `source_test.go`).
- Pitfalls & edge cases:
  - **Known limitation, document honestly:** redaction masks the *password*
    component only (net/url semantics). A driver that carries its secret in the
    host or port position — the Telegram token trick puts `<secret>` in the port
    component of `Addr()` — is **not** masked by `Redacted()`. Masking host/port
    generically would destroy the common DB case (you want `localhost:5432`
    visible). State this in godoc and in Risks so consumers do not treat
    `Redacted()` as safe for token-in-authority DSNs.
  - Pointer receiver (consistent with the type): `%v` on a bare
    `DataSourceMapper` **value** (not pointer) will still print the raw map and
    leak. Every constructor (`Parse`, `New`, `MustParse`, `Unmarshal`) returns a
    pointer, so the common path is protected; document the value caveat. (A
    value-receiver `String()` would protect both but breaks receiver consistency —
    see Trade-offs.)
  - Do not reimplement the format here — call `assembleDSN`; duplicating it
    recreates the two-homes leak Task 2 removed.
- Complexity: Easy

### Task 4: Stop parse errors from echoing the raw DSN

- Description: `Parse` leaks its input into error messages: `parser.go:99`
  formats `"invalid connection string format: %s"` with the raw `dns` (which
  carries bot tokens/passwords), and the `url.ParseQuery` failure at
  `parser.go:144-145` returns the stdlib error whose text can embed an offending
  fragment of the query string. Consumers `hive` (`cmd/queen/main.go`) and
  `vpntunnel` (`notify/dsn.go`) both discard the real error and substitute a
  generic message precisely to avoid this leak. Replace both with static,
  input-free plain errors. Per the project error contract, these are bad-input
  errors, so they are plain and sentinel-free (no `%w`, no input echo). This lets
  the two consumers surface the library error directly and delete their
  workarounds.
- Consumer rent: removes the error-swallowing wrappers in `hive` and `vpntunnel`
  (each replaces a real error with a hand-written generic string today).
- Acceptance Criteria:
  - `parser.go:99` becomes `return nil, errors.New("invalid connection string format")`
    (no `%s`, no `dns`).
  - The `url.ParseQuery` failure returns a static plain error such as
    `errors.New("invalid connection string query parameters")` — the raw input is
    never wrapped or echoed.
  - A test parses a DSN containing a recognizable secret (e.g.
    `not a dsn %zz SECRETTOKEN`) and asserts, for every error-producing path, that
    the returned `err.Error()` does **not** contain the secret substring.
  - `regexp.Compile` path unchanged.
- Pitfalls & edge cases:
  - Do not `%w`-wrap the `url.ParseQuery` error — its `EscapeError` text includes
    the bad fragment of the (untrusted) input. Static error only.
  - Error *text* is not part of the API contract (the house rule forbids
    comparing error strings), so changing the messages is non-breaking.
  - Keep the `Unmarshal` "could not recognize configuration" message (parser.go:38)
    — it is already input-free.
- Complexity: Easy

### Task 5: Typed option accessors `OptionInt`, `OptionBool`, `OptionDuration`

- Description: Add three methods on `*DataSourceMapper` that parse a query option
  with stdlib and fall back to a caller default on absent/empty/unparseable —
  killing the hand-rolled `strconv`/`time.ParseDuration` consumers wrap around
  `Option()`. Signatures mirror the existing variadic-default style of `Option`
  and `Addr`:
  - `func (dsm *DataSourceMapper) OptionInt(name string, defaultValue ...int) int`
    (via `strconv.Atoi`)
  - `func (dsm *DataSourceMapper) OptionBool(name string, defaultValue ...bool) bool`
    (via `strconv.ParseBool`)
  - `func (dsm *DataSourceMapper) OptionDuration(name string, defaultValue ...time.Duration) time.Duration`
    (via `time.ParseDuration`)
  Each returns the parsed value; on missing key, empty value, or parse error it
  returns `defaultValue[0]` if supplied, else the zero value. `time` is added to
  `source.go` imports (stdlib). These are methods on the concrete type only — the
  `DataSource` interface is not touched.
  For the separate string-empty pattern (`if v := dsn.Option("model"); v != ""`,
  repeated 3+ times in `beacon`, caused by `Option` returning the default only
  when the key is *absent*, not when present-but-empty — source.go:75-80): do
  **not** change `Option`'s semantics and do **not** add a near-duplicate string
  accessor. `Option` stays byte-for-byte backward compatible; recommend consumers
  use the stdlib `cmp.Or(ds.Option("model"), "fallback")` (Go 1.22+), which
  returns the first non-empty string in one line. Document this in the `Option`
  godoc. Rationale in Trade-offs.
- Consumer rent: replaces `ParseUint` on the mongodb `limit` and `Atoi` on the
  redis DB index in `com_lingocrm`, `parseDSNTimeout` (ParseDuration) in `beacon`,
  and the equivalent in `hive` — plus each site's error handling. The string-empty
  case is solved with zero new surface via `cmp.Or`.
- Acceptance Criteria:
  - `OptionInt("limit", 100)` returns `100` when `limit` is absent, empty, or
    non-numeric; returns the parsed int otherwise (including negatives).
  - `OptionBool("tls", true)` honors `strconv.ParseBool` inputs
    (`1/t/true/0/f/false`), else default.
  - `OptionDuration("timeout", 30*time.Second)` parses `"30s"`/`"5m"`, else
    default.
  - Each accessor returns the Go zero value when called with no default and the
    value is absent/empty/unparseable (matching the existing `Port()` swallow
    behavior).
  - One table-driven `Test*` per accessor covering: present-valid, present-empty,
    present-garbage, absent-with-default, absent-without-default.
- Pitfalls & edge cases:
  - `OptionDuration` is strict `time.ParseDuration`: a unit-less value like
    `"30"` is a parse error and yields the default. Document that values need
    units; consumers wanting bare-seconds use `OptionInt` + multiply.
  - Clamping (min/max bounds, as in `beacon`'s `parseDSNTimeout`) is consumer
    policy, not library concern — the accessor parses, the consumer clamps.
  - Do not add these to the `DataSource` interface (breaks consumer stubs).
- Complexity: Easy

### Task 6: `New` constructor with functional field options

- Description: Add a one-call, type-safe constructor so consumers stop
  hand-building `DataSourceMapper(map[string]string{...})` literals and can delete
  hand-rolled `DataSource` stubs (a `*DataSourceMapper` already satisfies the
  interface). Use functional options typed structurally as
  `func(*DataSourceMapper)` — deliberately **not** a named `Option` type, to avoid
  colliding with the existing `Option`/`OptionsNames` vocabulary:
  - `func New(options ...func(*DataSourceMapper)) *DataSourceMapper`
  - `func WithDriver(v string) func(*DataSourceMapper)`
  - `func WithHost(v string) func(*DataSourceMapper)`
  - `func WithPort(v int) func(*DataSourceMapper)`
  - `func WithLogin(v string) func(*DataSourceMapper)`
  - `func WithPassword(v string) func(*DataSourceMapper)`
  - `func WithDatabase(v string) func(*DataSourceMapper)`
  - `func WithOption(name, value string) func(*DataSourceMapper)`
  Each `WithX` delegates to the existing `SetX`/`SetOption` (which already
  allocate the map when nil). `New` starts from an empty `*DataSourceMapper` and
  applies each option. Placed at the top of `source.go` per File Declaration
  Order (constructor before struct).
- Consumer rent: replaces **24** map literals in `com_lingocrm` and **13** in
  `beacon`; makes `wordhunter`'s `stubDataSource`+`mockDSN` (~38 lines) and
  `beacon`'s `stubDataSource` (~14 lines) deletable; construction is now
  compile-checked per field, closing the `"username"` typo-bug class.
- Acceptance Criteria:
  - `New(WithDriver("postgres"), WithHost("localhost"), WithPort(5432))` returns a
    `*DataSourceMapper` whose `Driver()/Host()/Port()` return those values and
    whose other fields are absent.
  - `New()` returns a non-nil empty `*DataSourceMapper` usable everywhere a
    `DataSource` is expected.
  - `WithLogin("")`/`WithPort(0)` explicitly set those keys (functional options
    have no zero-value ambiguity).
  - `WithOption("sslmode", "disable")` sets a query option that appears in
    `OptionsNames()`.
  - A test constructs via `New(...)` and passes the result to a function typed
    `func(DataSource)` to prove interface satisfaction.
  - Table-driven `TestNew` covering field options, option options, and empty
    construction.
- Pitfalls & edge cases:
  - The option type is the structural `func(*DataSourceMapper)` (no named,
    exported type) specifically to avoid the "Option" word clash; do not
    introduce `type Option`.
  - `New` returning the concrete pointer is what makes stubs deletable — do not
    return the `DataSource` interface.
  - Keep the surface to exactly these eight symbols; do not add per-consumer
    convenience combos.
- Code Example:
  ```go
  func New(options ...func(*DataSourceMapper)) *DataSourceMapper {
      dsm := &DataSourceMapper{}
      for _, opt := range options {
          opt(dsm)
      }
      return dsm
  }

  func WithHost(v string) func(*DataSourceMapper) {
      return func(dsm *DataSourceMapper) { dsm.SetHost(v) }
  }
  func WithOption(name, value string) func(*DataSourceMapper) {
      return func(dsm *DataSourceMapper) { dsm.SetOption(name, value) }
  }
  ```
- Complexity: Easy

- Complexity: Easy

### Task 8: `Require` required-field validation

- Description: Add `func (dsm *DataSourceMapper) Require(keys ...string) error`
  that returns `nil` when every named key is present **and non-empty**, otherwise
  a single plain error naming **all** missing keys. All five consumers hand-code
  "field X must be non-empty or error" (telegram token+chatid, rclone remote, AI
  key, model). With Task 1's exported constants, callers write
  `ds.Require(dsninjector.KeyLogin, dsninjector.KeyPassword)` or
  `ds.Require("token", "model")` for options. Method on the concrete type; the
  interface is untouched.
- Consumer rent: replaces the hand-coded required-field checks in all five
  consumers (~3–8 lines each).
- Acceptance Criteria:
  - `Require()` with no keys returns `nil`.
  - `Require("login", "password")` returns `nil` when both are present and
    non-empty.
  - When keys are missing or empty, the error names every offending key, e.g.
    `missing required data source fields: login, password`.
  - The error is a plain error (no sentinel, no `%w`) per the bad-input contract,
    and names **keys only, never values** (naming the field `password` is safe;
    its secret value must never appear).
  - `TestDataSourceMapper_Require` covers: all-present, one-missing,
    present-but-empty, multiple-missing (assert all named), zero-keys.
- Pitfalls & edge cases:
  - "Present" must mean present **and non-empty** — a blank required field is as
    bad as an absent one; that is the consumer intent. Document it.
  - Report all missing keys in one error (deterministic order — iterate `keys` in
    argument order), not just the first, for usable diagnostics.
  - Never include the field *value* in the message.
- Complexity: Easy

### Task 9: Return the concrete type from `Unmarshal`/`UnmarshalOrEmpty`

- Description: Change `Unmarshal(key string, defaultValue ...string) (DataSource, error)`
  to `(*DataSourceMapper, error)` and `UnmarshalOrEmpty(...) DataSource` to
  `*DataSourceMapper`, so the primary env-loading entry points expose the new
  methods (Tasks 3, 5, 8) directly, without a type assertion. This is a
  static-type widening, not a runtime change: `UnmarshalOrEmpty` already only ever
  returns `*DataSourceMapper` values (the Parse result or `&DataSourceMapper{}`),
  and `Unmarshal` returns the Parse result or `nil`. The `DataSource` interface
  definition is **not** touched. Implement the skipped `TestUnmarshal` and
  `TestUnmarshalOrEmpty` to cover env-present, env-absent-with-default,
  env-absent-without-default (error / empty mapper), and to prove the new methods
  are callable on the results. Isolated as its own task so review can accept or
  reject the signature change independently — if rejected, consumers use
  `Parse`/`MustParse` (both return the concrete type) for typed access.
- Consumer rent: lets consumers call `OptionInt`/`Redacted`/`Require` on the
  env-loaded config directly (the most common config-reading path) instead of
  `Parse`-ing again or type-asserting.
- Acceptance Criteria:
  - Both functions return `*DataSourceMapper`; the `DataSource` interface is
    unchanged and `var _ DataSource = &DataSourceMapper{}` still holds.
  - `UnmarshalOrEmpty` never returns nil (empty `*DataSourceMapper` on failure).
  - `Unmarshal` returns `(nil, err)` on failure with the sanitized error.
  - `TestUnmarshal`/`TestUnmarshalOrEmpty` un-skipped and green; a test calls a
    new method (e.g. `OptionInt`) on the `Unmarshal` result to prove reachability.
  - `go build ./...`, `go vet ./...`, `go test -race .` green.
- Pitfalls & edge cases:
  - **Signature change (flag at review).** Callers that infer the variable type
    from `Unmarshal` and later reassign it to a *different* `DataSource`
    implementation get a compile error (fixed with an explicit `var ds DataSource`).
    This is a clear compile-time error, not a silent runtime break; low real-world

## Risks

- **`Marshal` output change (T2).** Plaintext creds replace base64; a consumer
  depending on the old (broken, unverified) output would break. Mitigation:
  classify `fix:`, flag at review; recon shows no such dependence.
- **`Unmarshal` signature change (T9).** Return-type widening can produce compile
  errors in the rare reassign-to-other-impl case, plus the typed-nil-in-interface
  gotcha. Mitigation: isolated task, documented, rejectable independently; the
  `Parse`/`MustParse` fallback keeps typed access available if T9 is dropped.
- **`Redacted()` false confidence (T3).** Masks the password component only;
  drivers carrying secrets in the authority (the Telegram token trick puts the
  secret in the port component of `Addr()`) are not masked, and a bare
  `DataSourceMapper` value logged with `%v` still leaks (pointer receiver).
  Mitigation: document both limitations prominently in godoc so consumers do not
  rely on `Redacted()` for token-in-authority DSNs; constructors return pointers
  so the accidental-`%v` path is covered for the common case.
- **Round-trip scope creep (T2).** Socket/file forms and percent-escaping do not
  round-trip; a reviewer may push for full correctness. Mitigation: explicit
  scope line and deferral to plan 003; `TestMarshal` asserts only network forms.
- **Merge coordination with plan 001 (parser.go).** Both plans touch `parser.go`;
  this plan changes error *text* and adds `MustParse`, plan 001 changes matching
  *logic*. Mitigation: different lines/concerns; coordinate at merge.
- **Surface growth vs. "stay small".** This plan adds ~19 exported symbols
  (6 constants, 3 accessors, 8 constructor funcs, `MustParse`, `Require`, and the
  `Redacted`/`String` methods). Each is rent-justified above; the review gate is
  the backstop, and the Deferred list shows what was consciously excluded.

## Trade-offs

- **`Option` empty-string handling: recommend `cmp.Or`, add no string accessor
  (chose stdlib reuse over a new method, and over changing `Option`).** Changing
  `Option` to fall back on present-but-empty is a subtle semantic break to the
  most-used method (a consumer that sets `?sslmode=` to mean "explicitly none"
  while passing a non-empty default would silently change behavior); "prefer
  non-breaking" rules it out. A dedicated `OptionOr` string method would duplicate
  what `cmp.Or(ds.Option(k), fallback)` already does in one stdlib line (Go
  1.22+), adding surface for ~3 line-savings in one consumer. Reused `cmp.Or`;
  documented it on `Option`.
- **Functional options over a `Config` struct for `New` (T6).** A `New(Config{...})`
  struct constructor is smaller surface (2 symbols vs 8) but has zero-value
  ambiguity (cannot distinguish "port unset" from `WithPort(0)`, "login unset"
  from `WithLogin("")`) and reads worse for partial fixtures. Chose functional
  options for precise, unambiguous partial construction and idiomatic
  extensibility, accepting the larger symbol count (justified by 37 map-literal
  sites + ~52 deletable stub lines).
- **Fix `Marshal` now vs. add a new `URL()` and defer (T2).** Adding a separate
  `URL()` round-trip serializer would leave the broken `Marshal` in place as a
  landmine and create two names for one concept. Chose to fix `Marshal` (the
  library's stated purpose) and route redaction through its shared assembler —
  one format home. Deferred only the deep `net/url`-engine correctness (escaping,
  socket forms) to plan 003.
- **Methods on the concrete type + widen `Unmarshal`'s return, over widening the
  interface or making everything free functions.** Widening `DataSource` is
  forbidden (breaks consumer stubs). All-free-functions would be universally
  interface-compatible but inconsistent with the library's method-heavy design
  (`Port`, `Addr`, `AuthBasicBase64` are methods). Chose methods on
  `*DataSourceMapper` (consistent, ergonomic) and made the env path return the
  concrete type so the methods are reachable there too.
- **Pointer receiver for `String()`/`Redacted()`, over value receiver (T3).** A
  value receiver would protect both `DataSourceMapper` and `*DataSourceMapper`
  from `%v` leaks but breaks receiver consistency with every other method on the
  type. Chose pointer receiver for consistency; documented the value-format
  caveat and that all constructors return pointers.
- **Document the Telegram field-repurposing convention, add no Telegram API (T3,
  Pattern 6).** The token-as-host / chatid-as-login wrapper is triplicated across
  three consumers, but the token shape is Telegram-specific; hardcoding it in a
  generic DSN library is wrong. Chose godoc documentation of the convention over a
  `Token()`/`ChatID()` API.

## Deferred to plan 003 (discussion)

Consciously excluded from this plan to keep scope tight; raise for discussion, do
not implement here:

- **`net/url` parsing engine** — proper percent-escaping/unescaping, IPv6 host
  literals, and full special-character round-trip (the limitation `Marshal`
  documents in T2).
- **Socket/file DSN round-trip** (`mysql:/path`, `sqlite:/path`, `file:name`) —
  needs the engine above.
- **Base-URL policy formatter** — the `scheme://addr/db` variants in
  `com_lingocrm` (~10x) and `beacon` differ by policy (https-fallback,
  loopback→http, drop-db); unifying them yields a shallow flag-driven module.
  Coincidental similarity that should stay duplicated; consumers compose from
  `Driver()`/`Addr()`/`Database()`.
- **`FromURL(*url.URL)`** — only `com_lingocrm` builds DSNs from a URL, and it
  builds from the *string* `httptest.Server.URL`, which `MustParse` already
  covers; would couple the public API to `net/url` for no clear rent.
- **Telegram-specific accessors** (`Token()`, `ChatID()`) — too domain-specific
  (Pattern 6).
- **Multi-host DSNs, driver alias tables, driver-native DSN generation** (libpq
  keyword/value, mysql DSN format), **struct-tag binding** (decode a DSN into a
  typed config struct), **`OptionFloat`** (no recon evidence).
- **Per-call `regexp.Compile` → package-level `var` (perf)** — `Parse` recompiles
  its regex every call; a behavior-neutral optimization, but an internal concern,
  not a consumer pattern.
- The DSN-**validity** bug (`https://google.com`, `tbot://TOKEN`) is plan 001, not
  this plan or 003.

The gate returned **REVISE** with two blocking findings, both administrative — the

### Blocking fix 1 — the acceptance gate command is unrunnable as written

`CGO_ENABLED=0 go test -race .` fails immediately with `-race requires cgo` on the

- `CGO_ENABLED=0 go vet ./...`,
- `CGO_ENABLED=0 go test .` (functional, no `-race`).

A race pass, if wanted, is a **separate optional** `CGO_ENABLED=1 go test -race .`
run on a cgo-capable toolchain — never folded into the CGO-disabled gate. (Plan
001 carries the identical caveat; `CLAUDE.md`'s stated `-race` gate is what needs
this reconciliation, tracked as a doc follow-up.)

### Blocking fix 2 — the consumer count is five, not six

There are exactly **five** real consumers: `com_lingocrm_api`, `beacon`, `hive`,
`wordhunter`, `vpntunnel`. The apparent "sixth" is
`hive/.claude/worktrees/agent-…/` — a stale git-worktree duplicate of `hive`,

### Blocking fix 3 — Task 2 round-trip AC is self-contradictory on empty credentials

`Parse(Marshal(Parse(src)))` **map-deep-equal** cannot hold for the existing
guardrail `mysql://:@localhost/dbname`: it parses with present-but-empty `login`
and `password` keys, but `assembleDSN` (correctly, per AC #2) omits the whole
credentials segment when both are empty, so the re-parse lacks those two keys and
map identity fails. Fix: Task 2 AC #1 compares round-trips at the **accessor**
level — `Driver/Host/Port/Login/Password/Database/OptionsNames` — not raw map
identity. `Login()`/`Password()` both return `""` either way, so accessor
equivalence holds; keep AC #2 unchanged. State the comparison mode explicitly.

### Blocking fix 4 — Task 4 leak test must use a genuinely-erroring input

`not a dsn %zz SECRETTOKEN` parses **successfully** (into `Database`), so it yields
no error to assert on, and the raw-echo branch (`parser.go:99`, `matches==nil`) is
effectively unreachable under the all-optional anchored regex — the no-leak assert
passes trivially and proves nothing. Fix: (a) exercise the reachable error path
with a secret adjacent to the offending fragment, e.g. `x://h/d?tok=%zzSECRET`
(invalid percent-escape in the query) → assert the returned error equals the new
static message **and** does not contain `SECRET`; (b) reframe Task 4 as
**defensive hardening**: drop the "for every error-producing path" claim, and note
the raw-echo branch is unreachable today but is sanitized regardless so it can
never leak if the regex is later loosened.
