# Task Breakdown

## Overview

`Parse` (`parser.go:89-155`) mis-parses any DSN that has no `://` authority
marker but *is* a host. The named-group regex (`parser.go:91`) treats the first
`[a-z+]+:` as a driver and dumps the remainder into `database` via
`path.Join("/", …)` (`parser.go:138`). Empirically verified against the current
package:

| Input | Current (bug) | Required |
|---|---|---|
| `google.com` | `database=/google.com`, host empty | `host=google.com` |
| `localhost` | `database=/localhost` | `host=localhost` |
| `localhost:5432` | `driver=localhost`, `database=/5432` | `host=localhost`, `port=5432` |
| `example.com:443` | `database=/example.com:443` | `host=example.com`, `port=443` |
| `1.2.3.4:5432` | `database=/1.2.3.4:5432` | `host=1.2.3.4`, `port=5432` |
| `./data/app.db` | `database=/data/app.db` (`./` stripped, `/` forced) | `database=./data/app.db` |

The confirmed product decision (already made — not re-litigated here) is
**"bare host + host:port"** semantics: a plain domain or `host:port` is a valid
DSN whose host/port land in `Host()`/`Port()`.

**Approach — minimal, regex-preserving.** The existing authority regex already
parses `host:port` *correctly* when the input is in `//host:port` form (verified:
`//localhost:5432` → host `localhost`, port `5432`). So rather than rewrite the
regex (that is the deferred `net/url` question, `.agents/plans/003` Topic 1), we add a
classifier at the top of `Parse` that reshapes scheme-less host / host:port
inputs into the authority form (`//…`) and routes a bare filesystem path to a
dedicated handler that preserves it verbatim. The authority regex and its
post-processing are extracted **byte-for-byte** into `parseAuthority` so every
one of the 16 existing success cases — and the Telegram token trick that rides on
the `://` path — is untouched.

The relative-path corruption (`path.Join("/", …)` at `parser.go:138`) is fixed as
a consequence: driverless bare paths never reach that line, because the new
`parseBarePath` assigns `Database()` directly. The `path.Join` line stays for the
driver-opaque form (`file:myfile.sqlite3` → `/myfile.sqlite3`), which is a locked
guardrail (`parser_test.go:104-107`).

**Out of scope (deferred, do not attempt here):**
- IPv6 authorities (`[::1]:6379`) — the `SplitN(instance, ":", 2)` at
  `parser.go:119` shreds them. Deferred to `.agents/plans/003` Topic 4 (rides on the
  `net/url` decision). This plan only guarantees IPv6 input does not panic.
- `Marshal` round-trip and un-skipping `TestMarshal`/`TestUnmarshal` — owned by
  `.agents/plans/002` and `.agents/plans/003` Topic 2. This plan introduces **no** normalization,
  so `Marshal` behavior is unchanged (see Trade-offs).
- Scheme-less credentialed forms (`user:pass@host:port` with no `://`) — the
  disambiguation rule classifies these as driver-opaque; not supported.

## Assumptions

1. **"host:port" trigger = colon immediately followed by an ASCII digit `0-9`.**
   This is the user-confirmed disambiguation rule. Consequence: `redis:6379`
   → host `redis`, port `6379`; and the pathological `file:123.db` → host `file`,
   port `123.db`. Accepted per the rule; documented as a known edge in Task 2.
2. **A bare token with no colon and no `/` is a host, not a filename.** So
   `app.db` → `host=app.db`. To denote a local file, callers use `./app.db`,
   `driver:app.db`, or the authority form. Documented, not "fixed".
3. **Query options are supported on the new bare forms** (`localhost:5432?ssl=on`,
   `./x.db?cache=shared`) for parity with the authority form; `?` always
   introduces the option tail, matching `parser.go:142-149`.
4. **No `source.go` change is required.** `Host()`, `Port()`, `Database()`,
   `Addr()` all read the map; setting the map correctly is sufficient. Verified.
5. **Trailing-slash normalization is intentionally NOT done** (see Trade-offs /
   Risks) — `https://host/` and `tbot://…/` keep `database="/"`.
6. **`Parse` does not trim input**; `Unmarshal` (`parser.go:36`) already trims
   before calling `Parse`. Unchanged.

### Task 1: Extract `parseAuthority`, hoist the regex, centralize option parsing

- **Description:** Behavior-preserving refactor of `Parse` (`parser.go:89-155`).
  (a) Move the compiled regex to a package-level unexported var
  `authorityRx = regexp.MustCompile(...)` so it is compiled once, not on every
  call. (b) Move the entire current body of `Parse` (from `FindStringSubmatch`
  through `return &ds, nil`) into a new unexported `parseAuthority(dns string)
  (*DataSourceMapper, error)`, keeping the `instance`/`credentials`/`path`/
  `params` post-processing **identical** — in particular the
  `path.Join("/", matches[i])` branch at `parser.go:136-141` must remain verbatim.
  (c) Replace the inline `case "params"` block (`parser.go:142-149`) with a call
  to a new helper `applyOptions(m map[string]string, raw string) error` that runs
  `url.ParseQuery` and folds values into `m`. For this task, `Parse` becomes a
  one-line delegate: `return parseAuthority(dns)`.
- **Acceptance Criteria:**
  - `CGO_ENABLED=0 go test -run 'TestParse/successful' .` — all 16 existing
    sub-cases pass unchanged (they are the guardrail; see Truth Table rows 1-16).
  - `gofmt -l .` prints nothing; `CGO_ENABLED=0 go vet ./...` clean.
  - No behavior change: `Parse` output is identical to pre-refactor for every
    existing input. No test assertions are modified in this task.
  - File Declaration Order (per `CLAUDE.md`) respected: exported funcs
    (`Marshal`, `Unmarshal`, `UnmarshalOrEmpty`, `InitEnvFrom`, `Parse`) stay at
    the top; then the unexported var `authorityRx`; then unexported funcs
    (`applyOptions`, `parseAuthority`, `parseBarePath` [Task 2], `readEnvVarName`),
    alphabetical.
  - Imports unchanged (`regexp`, `net/url`, `path`, `strings`, `fmt` all still used).
- **Pitfalls & edge cases:**
  - `regexp.MustCompile` panics on a bad pattern at init — acceptable because the
    pattern is a compile-time constant; it removes the (never-taken) error branch
    from `Parse`. Do not change the pattern string.
  - `applyOptions` must preserve the exact fold semantics: repeated keys joined
    with `,` (`strings.Join(v, ",")`), matching `parser.go:148`.
  - Do not "improve" the `path.Join` branch here — it is guardrail-critical for
    rows 7, 13, 14 and is corrected for the driverless case only in Task 2.
- **Complexity:** Medium (mechanical, but guardrail-sensitive).
- **Code Example:**
  ```go
  // unexported const/var region of parser.go
  var authorityRx = regexp.MustCompile(`(?i)^(?:(?P<driver>[a-z+]+):)?(?://(?:(?P<credentials>[^/@]+)@)?(?P<instance>[^/@]+))?(?:/?(?P<path>[^?]+))?(?:\?(?P<params>.*))?$`)

  func applyOptions(m map[string]string, raw string) error {
      q, err := url.ParseQuery(raw)
      if err != nil {
          return err
      }
      for k, v := range q {
          m[k] = strings.Join(v, ",")
      }
      return nil
  }
  ```

### Task 2: Add the scheme-less classifier and `parseBarePath`

- **Description:** Turn `Parse` into a classifier that dispatches on the shape of
  `dns` before delegating to `parseAuthority`. Implement the confirmed
  disambiguation rule **in this exact precedence order**:

  1. **`dns` contains `://`** → authority form. Delegate to `parseAuthority`
     unchanged (existing behavior; covers all `://` DSNs incl. the Telegram trick).
  2. **else first colon is immediately followed by an ASCII digit** (`word:5432…`)
     → **host:port**. Reshape to `"//" + dns` and delegate to `parseAuthority`
     (the regex then reads `instance = host:port`, splitting host/port correctly,
     and any `/database` / `?opts` tail falls out for free).
  3. **else a colon is present** (`word:/path`, `word:nondigit…`) → driver-opaque
     database. Delegate to `parseAuthority` unchanged (preserves rows 7, 13, 14).
  4. **else (no colon):** if `dns` contains `/` → **bare filesystem path**; hand
     to `parseBarePath` (database preserved verbatim). Otherwise → **bare host**;
     reshape to `"//" + dns` and delegate to `parseAuthority`.

  `parseBarePath(dns string) (*DataSourceMapper, error)` builds a map with all six
  reserved keys empty, splits off an optional `?opts` tail via `applyOptions`, and
  assigns the remaining substring **as-is** to `keyDatabaseName` (`source.go:96`).
  This is what fixes the relative-path bug: no `path.Join`, so `./data/app.db`
  stays `./data/app.db` and `/opt/app/x.db` stays `/opt/app/x.db`.
- **Acceptance Criteria:** (verify with a temporary probe or via Task 3 tests)
  - Rule 4b (bare host): `google.com`→`host=google.com`; `localhost`→`host=localhost`;
    all other reserved keys empty.
  - Rule 2 (host:port): `localhost:5432`→`host=localhost,port=5432`;
    `example.com:443`→`host=example.com,port=443`;
    `1.2.3.4:5432`→`host=1.2.3.4,port=5432`;
    `localhost:5432/mydb?ssl=on`→`host=localhost,port=5432,database=mydb,ssl=on`.
  - Rule 4a (bare path): `./data/app.db`→`database=./data/app.db`;
    `/opt/app/x.db`→`database=/opt/app/x.db`;
    `./data/wordhunter.db`→`database=./data/wordhunter.db` (recon regression).
  - All 16 guardrail rows still pass (`CGO_ENABLED=0 go test -run 'TestParse/successful' .`).
  - `Addr()` for the host:port rows equals `host:port` (e.g. `localhost:5432`),
    confirming `source.go:25-34` composes correctly.
  - `parseBarePath` output has exactly the six reserved keys plus any parsed
    options — matching the shape `parseAuthority` produces (so `require.Equal` on a
    `*DataSourceMapper` is consistent across code paths).
  - `gofmt -l .` clean; `CGO_ENABLED=0 go vet ./...` clean.
- **Pitfalls & edge cases:**
  - **Precedence is load-bearing.** The `://` check MUST run first: without it,
    `postgres://…` would match "colon-then-nondigit" and be misrouted. Verified:
    `postgres://…`'s first colon is followed by `/`.
  - **Do not recurse.** `"//" + dns` must be passed to `parseAuthority`, never back
    to `Parse` — `//localhost:5432` re-classifies as host:port and would loop.
  - Colon as the last char (`host:`) → `colon+1 < len(dns)` is false → falls to
    rule 3 (driver-opaque). Harmless; not a target case.
  - `file:123.db` and `redis:6379` classify as host:port per rule 2 (accepted
    ambiguity, Assumption 1). A bare `app.db` (no slash) classifies as host per
    rule 4b (Assumption 2). State both in code comments.
  - IPv6 (`[::1]:6379`): first colon at index 1 is followed by `:` (not a digit) →
    rule 3 → `parseAuthority` → non-crashing garbage (`database=/[::1]:6379`).
    Out of scope; must not panic (verified).
  - `parseBarePath` must init all six keys to `""` before setting database, or the
    resulting map won't equal the expected fixtures (which list all six keys).
- **Complexity:** Medium.
- **Code Example:**
  ```go
  // Parse reads the connection string and returns DataSource.
  func Parse(dns string) (*DataSourceMapper, error) {
      // A DSN without "://" may be a bare host, a host:port, a driver:opaque
      // string, or a filesystem path. The authority regex only understands the
      // authority form, so reshape a bare host / host:port into "//..." and send
      // a bare path straight to Database() unmangled.
      if !strings.Contains(dns, "://") {
          colon := strings.IndexByte(dns, ':')
          switch {
          case colon >= 0 && colon+1 < len(dns) && dns[colon+1] >= '0' && dns[colon+1] <= '9':
              dns = "//" + dns // host:port (colon immediately followed by a digit)
          case colon >= 0:
              // driver:opaque (e.g. "sqlite:/path", "file:x.db") — unchanged
          case strings.Contains(dns, "/"):
              return parseBarePath(dns) // bare filesystem path -> database, verbatim
          default:
              dns = "//" + dns // bare host (e.g. "google.com", "localhost")
          }
      }
      return parseAuthority(dns)
  }

  func parseBarePath(dns string) (*DataSourceMapper, error) {
      m := map[string]string{
          keyDriverName: "", keyHostName: "", keyPortName: "",
          keyLoginName: "", keyPasswordName: "", keyDatabaseName: "",
      }
      pathPart := dns
      if i := strings.IndexByte(dns, '?'); i >= 0 {
          pathPart = dns[:i]
          if err := applyOptions(m, dns[i+1:]); err != nil {
              return nil, err
          }
      }
      m[keyDatabaseName] = pathPart
      ds := DataSourceMapper(m)
      return &ds, nil
  }
  ```

## Risks

- **Guardrail regression during extraction (Task 1).** Mitigation: `parseAuthority`
  is a verbatim move; the `path.Join` branch is copied unchanged; the 16 existing
  cases run as the gate before Task 2 begins.
- **Precedence bug in the classifier.** If the `://` check is reordered after the
  colon check, `://` DSNs misroute. Mitigation: explicit ordering, a code comment,
  and rows 1-16 + 26-28 in the suite catch it immediately.
- **`-race` on this host.** The ARM sandbox reports `-race requires cgo`, which
  conflicts with the project's `CGO_ENABLED=0 go test -race .` gate. This is an
  environment/toolchain limitation, not a code issue; the race detector needs a
  cgo-capable toolchain. Run `CGO_ENABLED=0 go test .` + `go vet` here; run
  `-race` where a C toolchain exists (e.g. the user's dev machine). Flagged, not
  fixed — do not disable the gate.
- **Unknown consumer relying on the old bug.** A consumer that fed a bare domain
  and read `Database()` (getting `/google.com`) would now get `host=google.com`.
  This is the intended fix, but any such consumer must be re-checked. The known
  consumers (beacon/hive/wordhunter/vpntunnel) use the `://` or bare-path forms,
  which are covered by rows 23-28.

## Trade-offs

- **Reshape-to-authority over regex rewrite (chose normalization over `net/url`).**
  Prepending `//` and reusing the existing regex is a ~15-line change that leaves
  the 16 guardrails and the Telegram trick provably intact. A `net/url`-based
  rewrite would fix IPv6 and percent-encoding "for free" but is a behavior-shifting
  redesign — explicitly deferred to `.agents/plans/003` Topic 1, which must be sequenced
  *after* this plan so its compat sweep tests the final scheme-less truth table.
- **Dedicated `parseBarePath` over reusing the regex for paths (chose a handler).**
  The regex's `/?` (`parser.go:91`) eats one leading slash, so `/opt/app/x.db`
  would arrive as `opt/app/x.db`. Assigning the substring verbatim in a small
  handler is both simpler and the only way to preserve relative *and* absolute
  paths exactly. The 6-line option-tail parse is shared via `applyOptions` (a
  genuine cross-cutting invariant — option semantics must be identical
  everywhere), not duplicated.
- **Trailing-slash left as-is (chose no normalization over `/`→`""`).** Reasons:
  (1) outside the stated bug; (2) beacon reads `Database()` for its api-dsn and a
  `/`→`""` change could alter URL composition — unverifiable without beacon's
  source; (3) Telegram consumers read only `Addr()`/`Login()`, so there is zero
  upside for the load-bearing cases; (4) `Marshal` always emits `/` before
  `database`, so `""` vs `"/"` interacts with the deferred round-trip work.
  Revisit only if a real consumer needs it.
- **`Marshal` untouched (no normalization introduced).** Because this plan changes
  only how scheme-less *input* is parsed and adds no output normalization,
  `Marshal` behavior is unchanged. Note the pre-existing limitation: `Marshal`
  always emits `driver://auth@addr/db`, so it cannot faithfully round-trip the new
  scheme-less forms (`google.com` → `Marshal` → `://@google.com/`). That is the
  `Marshal`-round-trip concern owned by `.agents/plans/002` / `.agents/plans/003` Topic 2, and is
  why `TestMarshal` stays skipped here — one plan per concern.
```

### Blocking fix 1 — route the driver-less `//authority` form to `parseAuthority`

`//host/db`, `//host`, and `//localhost:5432/mydb` parse correctly today, and
plan 002's `Marshal` emits the `//host/db` shape for driver-less DSNs. The
original classifier gated only on `!strings.Contains(dns, "://")`, so it reshaped
these and mangled them (`//host/db` → `database="//host/db"`;
`//localhost:5432/mydb` → `////…`). Fix: treat a leading `//` as an authority
form and hand it straight to `parseAuthority`.

### Blocking fix 2 — peel the `?opts` tail before reshaping

The authority regex's instance group `[^/@]+` includes `?`, so reshaping
`localhost:5432?ssl=on` → `//localhost:5432?ssl=on` yields `port="5432?ssl=on"`
(the option tail is swallowed whenever there is no `/path` before the `?`). Fix:
strip a trailing `?opts` from scheme-less input first, classify/parse the
remaining host or path, then fold the options back in via `applyOptions`.
`parseBarePath` no longer needs its own `?` handling.

### Corrected `Parse` and `parseBarePath` (authoritative)

```go
// Parse reads the connection string and returns DataSource.
func Parse(dns string) (*DataSourceMapper, error) {
	// Authority forms — "scheme://…" and the driver-less "//…" — are understood
	// by the regex directly. Everything else is scheme-less: a bare host, a
	// host:port, a driver:opaque string, or a filesystem path.
	if strings.Contains(dns, "://") || strings.HasPrefix(dns, "//") {
		return parseAuthority(dns)
	}
	// Peel a trailing "?opts": the reshaped authority regex would otherwise let
	// the instance group ([^/@]+, which includes '?') swallow it when there is
	// no "/path" separator before the query.
	opts := ""
	if q := strings.IndexByte(dns, '?'); q >= 0 {
		opts, dns = dns[q+1:], dns[:q]
	}
	var (
		ds  *DataSourceMapper
		err error
	)
	switch colon := strings.IndexByte(dns, ':'); {
	case colon >= 0 && colon+1 < len(dns) && dns[colon+1] >= '0' && dns[colon+1] <= '9':
		ds, err = parseAuthority("//" + dns) // host:port (colon immediately before a digit)
	case colon >= 0:
		ds, err = parseAuthority(dns) // driver:opaque — sqlite:/path, file:x.db (unchanged)
	case strings.Contains(dns, "/"):
		ds, err = parseBarePath(dns) // bare filesystem path -> Database(), verbatim
	default:
		ds, err = parseAuthority("//" + dns) // bare host — google.com, localhost
	}
	if err != nil {
		return nil, err
	}
	if opts != "" {
		if err = applyOptions(*ds, opts); err != nil {
			return nil, err
		}
	}
	return ds, nil
}

// parseBarePath maps a scheme-less filesystem path straight to Database(),
// preserving it verbatim (this is what fixes the path.Join relative-path
// corruption at parser.go:138). The "?opts" tail is already stripped by Parse.
func parseBarePath(dns string) (*DataSourceMapper, error) {
	m := map[string]string{
		keyDriverName: "", keyHostName: "", keyPortName: "",
		keyLoginName: "", keyPasswordName: "", keyDatabaseName: dns,
	}
	ds := DataSourceMapper(m)
	return &ds, nil
}
```

Note: `applyOptions(*ds, opts)` mutates the same underlying map `ds` points to
(maps are reference types), so the options land on the returned value.
